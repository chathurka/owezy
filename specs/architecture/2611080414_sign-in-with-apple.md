## Scope

API Apple auth endpoint + oauth identity persistence; user-web Apple button + BFF; mobile Apple button + GetX flow. Admin out of scope.

---

## Architecture Overview

```
[User web Apple JS] ──BFF POST /api/auth/apple──► [Nest AuthController POST /v1/auth/apple]
[Mobile sign_in_with_apple] ──Dio─────────────────►              │
                                                                  ▼
                                                         AuthService.signInWithApple()
                                                                  │
                    ┌─────────────────┬───────────────────────────┼──────────────────┐
                    ▼                 ▼                           ▼                  ▼
           AppleTokenVerifier   findByAppleSub          findActiveByEmail      issueTokens()
           (JWKS / jose)        oauth_identities         (link or create)
```

---

## Key Design Decisions

- Public `POST /v1/auth/apple` with `@Public()`.
- `AppleTokenVerifier` port + JWKS adapter (mockable in unit tests).
- `oauth_identities` table with soft delete; unique active `(provider, provider_subject)`.
- Nullable `users.password_hash` for Apple-only users.
- Linking order: Apple `sub` → email match (active, non-deleted) → create.
- Conflict when email user already linked to a different Apple `sub` → `ACCOUNT_LINK_CONFLICT`.
- New Apple users: `role: user`, `emailVerified: true` when Apple asserts email, `defaultCurrency: USD` until profile onboarding changes it.
- Google buttons stay disabled.

## Data model

**Migration:**

1. `ALTER TABLE users ALTER COLUMN password_hash DROP NOT NULL`
2. Table `oauth_identities`:
   - `id` uuid PK
   - `user_id` uuid FK → users
   - `provider` varchar (`apple`)
   - `provider_subject` varchar (Apple `sub`)
   - `email` varchar nullable (last seen)
   - `created_at`, `updated_at`, `deleted_at`
   - Unique index on `(provider, provider_subject)` where `deleted_at IS NULL`

## Auth / authorization

- Endpoint public; always provisions/signs in `role: user` only.
- Issued JWTs identical to login (ADR-0001).
- Admin cannot be created or elevated via Apple.

## AI Resolutions

- Design: adapted from existing auth screens (no dedicated Apple mock).
- Default currency `USD` for Apple-created users.
- `authorizationCode` accepted but unused in MVP (token verify only); reserved for future Apple server revoke.
- Fail closed on JWKS errors as `INVALID_APPLE_TOKEN`.
- Soft-deleted users not revived on email match.
