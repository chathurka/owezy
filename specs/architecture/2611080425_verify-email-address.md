## Scope

API verify + resend; user-web `/verify-email`; mobile Verify email GetX feature. Admin n/a.

---

## Architecture Overview

```
[User web /verify-email?token] ──► POST /v1/auth/email/verify
[Mobile VerifyEmailPage code] ───► POST /v1/auth/email/verify
[Resend controls] ───────────────► POST /v1/auth/email/resend ──► EmailPort
                                         │
                                         ▼
                              AuthService.verifyEmail / resendVerification
                                         │
                              UserRepository consume token / rotate token
```

---

## Key Design Decisions

- Public endpoints; resend never enumerates accounts.
- 6-digit numeric codes; hashed at rest (same table).
- Cooldown via latest unconsumed/created token timestamp.
- Register path updated to issue 6-digit codes (same hash pipeline).

## NestJS module design (`apps/api/`)

| Method | Path | Guard | Response |
|--------|------|-------|----------|
| POST | `/v1/auth/email/verify` | `@Public()` | 200 `{ data: { email, emailVerified: true } }` |
| POST | `/v1/auth/email/resend` | `@Public()` | 204 |

Public verify/resend. No role elevation.

## Flutter feature design

`VerifyEmailPage` + `VerifyEmailController` + binding; route `/verify-email`; 6 digit boxes; resend countdown; success → home or login.

---

## Next.js user-web

`/verify-email` page: auto-submit token from query; show success / invalid + resend form. BFF optional (can call API from client for public routes) — prefer BFF `POST /api/auth/verify-email` and `/api/auth/resend-verification` for consistency.
