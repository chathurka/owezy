## Scope

API Google auth endpoint + oauth identity persistence (`provider: google`); user-web Google button + BFF; mobile Google button + GetX flow. Admin out of scope.

---

## Architecture Overview

```
[User web GIS] ──BFF POST /api/auth/google──► [Nest AuthController POST /v1/auth/google]
[Mobile google_sign_in] ──Dio───────────────►              │
                                                            ▼
                                                   AuthService.signInWithGoogle()
                                                            │
              ┌─────────────────┬───────────────────────────┼──────────────────┐
              ▼                 ▼                           ▼                  ▼
     GoogleTokenVerifier   findByGoogleSub         findActiveByEmail      issueTokens()
     (JWKS / jose)         oauth_identities         (link or create)
```

---

## Key Design Decisions

- Public `POST /v1/auth/google` with `@Public()`.
- `GoogleTokenVerifier` port + JWKS adapter (mockable in unit tests).
- Reuse `oauth_identities`; no new migration (table + nullable password already from E01-S04).
- Linking order: Google `sub` → verified email match (active, non-deleted) → create.
- Require `email_verified` from Google claims before create/link by email; otherwise `GOOGLE_EMAIL_REQUIRED`.
- Conflict when email user already linked to a different Google `sub` → `ACCOUNT_LINK_CONFLICT`.
- New Google users: `role: user`, `emailVerified: true`, `defaultCurrency: USD`.
- Apple buttons remain enabled; Admin unchanged.

## Data model

No new tables. Reuse:

- `oauth_identities.provider = 'google'`
- Unique active `(provider, provider_subject)` (already present)
- `users.password_hash` nullable (already present)

## Auth / authorization

- Endpoint public; always provisions/signs in `role: user` only.
- Issued JWTs identical to login (ADR-0001).
- Admin cannot be created or elevated via Google.

## AI Resolutions

- Design: adapted from existing auth screens (no dedicated Google mock).
- Default currency `USD` for Google-created users (parity with Apple).
- Require Google `email_verified` for email-based create/link; `sub`-only sign-in when already linked.
- Fail closed on JWKS errors as `INVALID_GOOGLE_TOKEN`.
- Soft-deleted users not revived on email match.
- No migration: reuse E01-S04 `oauth_identities`.
