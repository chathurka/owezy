## Scope

API (`AuthModule` login + logout), user-web Sign in screen + BFF login proxy (reuse existing logout BFF), mobile Sign in feature (GetX). Admin web out of scope.

---

## Architecture Overview

```
[User web SignIn] ──BFF POST /api/auth/login──► [Nest AuthController]
[Mobile LoginPage] ──Dio POST /v1/auth/login──►          │
                                                        ▼
                                              AuthService.login()
                                                        │
                         ┌──────────────────────────────┼──────────────────┐
                         ▼                              ▼                  ▼
                UserRepository.findActiveByEmail   bcrypt.compare    JwtService
                                                                        │
                                                                        ▼
                                                         access + refresh JWT

[Sign out] ── BFF/clear cookies or SessionService.clear ──► POST /v1/auth/logout (idempotent)
```

---

## Key Design Decisions

- Public `POST /v1/auth/login` with `@Public()`.
- Uniform `401` `INVALID_CREDENTIALS` for unknown email, wrong password, and soft-deleted users (no enumeration).
- Reuse JWT issuance helpers from register (same access/refresh secrets and TTLs per ADR-0001).
- Login response mirrors register session fields (tokens + user profile) without `emailVerificationRequired`.
- `POST /v1/auth/logout` is `@Public()` and returns `204` with no body; server-side refresh revocation deferred (ADR-0001 Phase 2). Clients always clear local session.
- “Keep me signed in / Remember me” UI only — refresh TTL stays 7d for MVP.
- Social buttons disabled placeholders; forgot-password is a non-functional or stub link.
- No schema migration — uses existing `users` from E01-S01.

## Data model

No new tables. Uses `users` from E01-S01 (`password_hash`, `deleted_at`, role, profile fields). Soft-deleted rows are excluded by `findActiveByEmail`.

---

## Auth / authorization

- Login/logout public.
- Issued JWTs: `{ sub, email, role }` access; `{ sub, type: 'refresh' }` refresh.
- End-user sessions expected `role: user` on user-web/mobile; API does not reject `admin` password login if such a row exists (admin console login remains a separate story).

## Flutter feature design (`apps/mobile/lib/features/auth/`)

Extend existing auth feature (do not invent a second module):

| Piece | Notes |
|-------|-------|
| `AuthRemoteDataSource` | `@POST('/auth/login')`, optional logout call |
| Models | `LoginRequestModel` / `LoginResponseModel` (json_serializable); reuse session/user mapping with register where possible |
| `AuthRepository` | `login(email, password)` → `AuthSession` |
| `LoginUseCase` | Thin domain use case |
| `LoginController` | GetxController + `.obs` fields: email, password, showPassword, rememberMe, field errors, submitting, form error |
| `LoginPage` | `GetView<LoginController>`; match SignIn.dc.html: logo+title, social disabled, email/password with eye toggle, Remember me + Forgot link, primary Sign in, Create account link |
| `LoginBinding` | `Get.lazyPut` controller + deps |
| Routes | Register `AppRoutes.login` in `AppPages`; set initial unauthenticated entry to login (register reachable via link); after success `Get.offAllNamed(AppRoutes.home)` via `SessionService` |

Widgets: reuse `RegisterFormField` / `lib/core/widgets/` (`AppButton`, `AppTextField` / chip patterns) — no raw Material chrome when Owezy primitives exist.

## AI Resolutions

- No Sign in PNGs in web/mobile screenshot folders — HTML mocks are visual source of truth; Design column documents paths.
- Logout API is public/idempotent 204; no refresh blacklist yet.
- Skip welcome interstitial on web/mobile after login; navigate straight to home/dashboard entry.
- Remember me UI only; JWT refresh TTL unchanged (7d).
- Mobile initial route should prefer login for returning users; register remains linked from Sign in (change `AppPages` initial from register → login).
- Reuse existing auth feature package on mobile rather than a parallel `login` feature root.
