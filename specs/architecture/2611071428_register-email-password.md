## Scope

API (`AuthModule` + `users` / verification persistence), user-web Sign up screen + BFF register proxy, mobile register feature (GetX). Admin web out of scope.

---

## Architecture Overview

```
[User web SignUp] ──BFF POST /api/auth/register──► [Nest AuthController]
[Mobile RegisterPage] ──Dio POST /v1/auth/register──►        │
                                                             ▼
                                                   AuthService.register()
                                                             │
                              ┌──────────────────────────────┼──────────────────────────┐
                              ▼                              ▼                          ▼
                     UserRepository                   EmailPort (Resend)         JwtService
                     (users + email_verification_tokens)                            │
                                                                                    ▼
                                                                     access + refresh JWT
```

---

## Key Design Decisions

- Single `POST /v1/auth/register` public endpoint; `@Public()`.
- Atomic user create + password hash + verification token row in one DB transaction.
- Issue JWT pair on success with `emailVerified: false` (soft gate deferred to E01-S05).
- Hash verification secrets with SHA-256 before storage; never log plaintext tokens/passwords.
- Email send is best-effort after commit; failures do not roll back the account.
- Social OAuth UI placeholders only — no provider calls.
- Users table is not a syncable offline entity; server-generated UUID; still include `deleted_at`.

## Auth / authorization

- Register is public (`security: []` / `@Public()`).
- Issued access JWT claims: `sub`, `email`, `role` (`user`).
- Refresh JWT signed with refresh secret; opaque to clients.
- Role admin cannot be self-assigned via register.
