## Summary

Authorized group members create invitations with expiry and status. Invitees must authenticate before accepting (E03-S04). Invalid, expired, revoked, and reused invitations are rejected safely. Group shareable `inviteCode` remains available alongside token invitations.

## Functional Requirements

- Members can create an invitation for a group (optional email label).
- Invitations expire after a fixed TTL; status is pending until accepted/revoked/expired.
- Members can list invitations and revoke pending ones.
- Non-members cannot create/list/revoke.
- Soft deletes on invitation rows.

## Role-Based Access

| Role | Permitted actions |
|------|-------------------|
| admin | n/a |
| user (member/owner) | Create, list, revoke invitations for their groups |

## Acceptance Criteria

- `POST /v1/groups/{id}/invitations` → 201 with invitation metadata + one-time `token` plaintext.
- Expired / revoked invitations cannot be accepted later (S04).
- `POST .../revoke` → status revoked.
- Non-member → 404 `GROUP_NOT_FOUND`.
- Clients show invite UI (share token / code) on group overview.

## Technical Notes

- Table `group_invitations`; token stored as SHA-256 hash; TTL 7 days.
- Email delivery out of scope — return token for client share; optional `email` field is a label only.

## Edge Cases

- Revoke already-accepted → 409.
- Soft-deleted group → 404.
