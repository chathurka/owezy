## Summary

After authentication, new users complete a short initial profile setup so group members can recognize them. Essential fields are validated before the user continues into the app; the same fields remain editable later (E02-S05). Parent epic: [#108](https://github.com/chathurka/owezy/issues/108).

## Functional Requirements

- Authenticated users can read their profile (`GET /v1/users/me`).
- Authenticated users can update profile fields used for recognition (`PATCH /v1/users/me`).
- Essential field for initial setup: `fullName` (trimmed, 1–100 chars).
- Optional on initial setup: `phone` (E.164-ish free text, max 32), `paymentHandle` (max 64, optional `@` prefix).
- Avatar upload is out of scope; clients show initials from `fullName`. `avatarUrl` may be stored as null.
- Completing or confirming setup sets `profileSetupCompletedAt` so the client does not re-prompt.
- After login/register/verify/social success, if `profileSetupCompletedAt` is null, clients route to the setup screen before home.
- Users may continue once essential validation passes; non-essential fields can be left empty.
- Profile can be edited later from settings (E02-S05); this story only ships the first-run setup UI.

## Acceptance Criteria

- `GET /v1/users/me` returns current user profile including `profileSetupCompletedAt`.
- `PATCH /v1/users/me` with valid `fullName` updates profile and can set `profileSetupCompletedAt`.
- Empty/whitespace `fullName` → 422 validation error.
- Unauthenticated → 401.
- Mobile and user-web show initial profile setup after auth when setup is incomplete.
- Successful setup navigates to home (further onboarding in E02-S04).
- Design chrome matches Profile/Settings personal-details patterns (adapted — no dedicated first-run mock).

## Edge Cases & Test Scenarios

- User already has `fullName` from register/social → setup pre-fills; confirming sets `profileSetupCompletedAt`.
- Soft-deleted user cannot authenticate; no profile access.
- Concurrent PATCH: last write wins on scalar fields (no versioning in MVP).
- Offline mobile: show error state; do not mark local setup complete without server ack.
