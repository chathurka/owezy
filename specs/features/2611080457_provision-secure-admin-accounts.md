## Summary

Authorized operators provision Admin accounts (no public registration). Admins sign in with email/password only (no Google/Apple). MFA (TOTP) is supported and recommended. Server-side role checks protect every admin operation. Access Denied and Session Expired states are provided. Admin forgot-password and email-verification screens are excluded. Parent epic: [#107](https://github.com/chathurka/owezy/issues/107).

## Functional Requirements

- Bootstrap or admin-only provision creates `role: admin` users with email/password.
- Admin console login uses email/password; rejects non-admin credentials for admin BFF.
- Optional TOTP MFA: when enabled, login returns an MFA challenge; verify code issues session.
- Access Denied page for authenticated non-admin hitting admin routes (middleware already redirects; dedicated page for 403 from API).
- Session Expired already covered by E01-S07; keep on admin login.
- No public admin register, forgot-password, or email-verify screens.

## Acceptance Criteria

- Provision endpoint requires admin JWT; creates admin with hashed password.
- Bootstrap via env creates first admin when none exists (dev/ops).
- Admin login with user-role credentials → admin BFF rejects / safe error.
- MFA-enabled admin must complete TOTP before cookies are set.
- Access Denied route renders for forbidden access.
- No Apple/Google on admin login; no forgot/verify screens.

## Technical Notes

- Design: `resources/owezy-admin-console/Sign in — Light-html/Login.dc.html`, Two-step verification HTML.
- OpenAPI: `POST /v1/admin/accounts`, `POST /v1/auth/mfa/verify`, `POST /v1/auth/mfa/setup` (admin self).
- Columns: `mfa_enabled`, `mfa_secret` on users (nullable secret).

## Edge Cases

- Last admin cannot be soft-deleted via this story (out of scope delete).
- Invalid TOTP → 401 `INVALID_MFA_CODE`.
