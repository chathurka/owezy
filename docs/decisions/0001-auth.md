# ADR-0001: Authentication

**Status:** accepted  
**Date:** 2026-11-01

## Context

Owezy needs to authenticate users across four surfaces (API, admin web, user web, mobile) with secure token handling and support for offline use on mobile.

## Decision

**NestJS-issued JWT** (access token + refresh token). No third-party identity provider at MVP.

- API issues access tokens (15m) and refresh tokens (7d) after email/password login.
- Flutter stores both tokens in `flutter_secure_storage`; `RequestInterceptor` injects `Bearer` header.
- Web apps store tokens in httpOnly cookies (`owezy_access_token`, `owezy_refresh_token`).
- BFF route handlers (`app/api/auth/refresh`) proxy refresh requests to the Nest API and re-set cookies.
- Admin web verifies `role === 'admin'`; user web verifies `role === 'user'` in middleware.
- Roles: `admin` (platform admin) and `user` (end user).

## Rationale

Self-hosted JWT avoids third-party dependency cost and complexity at MVP scale. The architecture is compatible with future OIDC/Social login without breaking the token contract.

## Consequences

- A key rotation process must be documented before production launch.
- Refresh token revocation requires a token blacklist (or short TTL) — Phase 2.
- No Amplify/Cognito or Google OAuth at MVP; can be added via a new ADR.
